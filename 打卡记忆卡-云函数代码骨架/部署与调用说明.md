## 2. 三步部署（微信开发者工具）

1. **放对位置**：在小程序项目根目录建 `cloudfunctions/`（若未建），把 `getToday/`、`importAnkiCsv/`、`checkin/`、`submitReview/` **四个**文件夹整体拷进去。确认 `project.config.json` 里有 `"cloudfunctionRoot": "cloudfunctions/"`。
2. **装依赖**：分别进入四个云函数目录，右键 →「在终端中打开」→ 执行 `npm install`（会按 `package.json` 装 `wx-server-sdk`）。这一步只需本地调试时需要；仅云端部署可跳过（云端会自动装）。
3. **上传部署**：在开发者工具里分别右键四个云函数目录 →「上传并部署：云端安装依赖」。首次部署约 1–3 分钟（冷启动），之后快。部署完在云开发控制台「云函数」页能看到四个函数。前端骨架见 `前端接入骨架/接入说明.md`。

> 环境：代码用 `cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV })`，会自动落到函数所在环境，无需改环境 ID。
> 运行时：Node.js（默认即可，代码只用了标准库 + wx-server-sdk，无平台相关依赖）。

## 3. 数据库准备（集合 + 索引 + 权限）

### 3.1 建 4 个集合

在云开发控制台「数据库」建：`users`、`plans`、`cards`、`reviews`（字段定义见实现要点 §1）。**建议建第 5 个 `checkins`**——`checkin` 云函数靠它做「固定 `_id=openid_date`」幂等防重，且 `submitReview` 会往当天流水的 `reviewedCount` 原子累加；不要建的话需同步改这两个函数（去掉流水读写），不推荐。日历视图也依赖它。

### 3.2 建索引（否则数据一多查询变慢且多耗调用）

| 集合 | 索引字段 | 用途 |
|---|---|---|
| `users` | `_openid`（唯一） | 按用户取统计 |
| `plans` | `_openid` + `enabled` | 取启用打卡项 |
| `cards` | `_openid` + `deckId`；`_openid` + `tags`；`ankiGuid` | 分组/标签/去重查询 |
| `reviews` | **`_openid` + `dueDate`** | 「取今日到期卡」的核心查询，务必建 |

### 3.3 权限模型（⚠️ 本方案最关键的一节）

这里有个**官方口径冲突**必须讲清，不能想当然：

- **常见说法**（社区多数帖 + 部分教程）：「云函数以管理员身份运行，绕过所有数据库权限，能读写任意集合」。
- **腾讯云开发官方文档**（`docs.cloudbase.net/recipes/add-cloud-function-wechat-miniprogram`，抓取 2026-11-12）明确写：**「云函数的执行身份继承调用方 OPENID，不是 admin」**，并给出报错 `-502005 DATABASE_PERMISSION_DENIED`：云函数访问集合时若权限是「仅创建者可读写」、而调用方 OPENID 不是文档创建者，会被拒。

两套来源互相矛盾，**本方案不赌任何一套**，用「防御性双重设计」让它两种情况下都正确：

1. **集合权限统一设为「仅管理端可读写」**：前端不直连数据库，所有读写都走这两个云函数（及后续补的打卡/复习反馈函数）。这样无论底层把云函数当 admin 还是当调用方身份，「仅管理端」都放行云函数。
2. **每个云函数强制用 `cloud.getWXContext().OPENID` 过滤**，绝不信任前端传来的 openid。这样即使云函数真继承了调用方身份，也只能查到自己的数据；即使云函数是 admin，也主动按 openid 隔离，不会串号。
3. **云函数 `add` 时显式写 `_openid`**：官方社区多条一致结论——小程序端 add 会自动注入 `_openid`，**云函数端不会**（来源：微信开放社区「云开发能力基础讲解」「使用云函数向云数据库插入记录需要手动添加openid么」）。`importAnkiCsv` 已在每条 `cards`/`reviews` 记录里显式写入 `_openid: openid`。

> 一句话：**权限设「仅管理端」+ 云函数内按 OPENID 过滤 + 写库带 `_openid`，三条一起做，不依赖任何一派口径。**

## 4. 小程序端调用示例

### 4.1 取当天待办（`getToday`）

```js
wx.cloud.callFunction({
  name: 'getToday',
  data: { date: '2026-11-12' }, // 可选，不传用云函数当天日期
  success(res) {
    const d = res.result
    if (d.code === 0) {
      // d.user      用户统计（streak/checkinDays...）
      // d.plans     启用的打卡项数组
      // d.reviews   今日待复习排程，每项带 .card 正文（缺失为 null）
      // d._meta.dbReadCalls  本次实际读调用数，可用于对账资源点
      this.setData({ user: d.user, plans: d.plans, reviews: d.reviews })
      // 建议：成功后把结果写入 wx.setStorageSync 作本地缓存，下次秒开再增量同步
    }
  },
})
```

### 4.2 导入 CSV（`importAnkiCsv`）

见 `CSV导入格式规范.md` §7 的完整片段。返回 `inserted / dupInFile / dupInDb / failed / approxWriteCalls`。

### 4.3 云函数返回约定

| 函数 | 成功 | 常见错误码 |
|---|---|---|
| `getToday` | `code:0` + `user/plans/reviews/_meta` | `401` 无 OPENID（非小程序调用）、`500` 数据库异常 |
| `importAnkiCsv` | `code:0` + `inserted/dupInFile/dupInDb/failed` | `400` CSV 格式/校验错、`401` 无 OPENID、`413` 超 2000 行、`500` 异常 |

## 5. 入参 / 出参表

### `getToday`

| 参数 | 方向 | 类型 | 说明 |
|---|---|---|---|
| `date` | 入 | string | 可选，`YYYY-MM-DD`；不传用云函数当天 |
| `user/plans/reviews` | 出 | object/array | 聚合结果；`reviews[].card` 为关联正文 |
| `_meta.dbReadCalls` | 出 | number | 本次读调用数，用于对账是否落在省档 |
| `_meta.truncated` | 出 | boolean | 待复习超 `MAX_DUE=500` 时为 true，前端应提示分批 |

### `importAnkiCsv`

| 参数 | 方向 | 类型 | 说明 |
|---|---|---|---|
| `csv` | 入 | string | CSV 文本（格式见规范文档） |
| `inserted / dupInFile / dupInDb / failed` | 出 | number | 导入统计 |
| `approxWriteCalls` | 出 | number | ≈ `inserted × 2`（每卡 cards+reviews），用于对账资源点 |

## 6. 上线前必做清单

- [ ] **集合权限设「仅管理端可读写」**，前端不直连数据库（见 §3.3 防御设计）。
- [ ] **索引建齐**，尤其 `reviews(_openid, dueDate)`。
- [ ] **免费环境上线后第 15 天到期** → 提审前升级个人版（19.9 元/月限时，原价 39）——这条与用量无关，是政策硬门槛。
- [ ] 个人版开启**按量付费/资源包**与**余额低于 10% 告警**，防意外停服（免费版不能开按量、用完直接停）。
- [ ] **压测导入上限**：用 2000 行真实 CSV 跑一次 `importAnkiCsv`，若超 15s 超时，调小 `MAX_ROWS` 或改前端分片多次调用（云函数默认超时 15s，官方「云函数端初始化」页 timeout 字段）。
- [ ] **压测复习批量**：`submitReview` 单次上限 `MAX_ITEMS=100`，用 100 张卡实测是否在 15s 内；超则调小。前端 `review.js` 已按 100 分批。
- [ ] **SM-2 取整口径已按官方**：间隔小数 **向上取整（ceil）**，不是四舍五入（round）。官方 SuperMemo 原文「如果间隔是个小数，则向上取整为最接近的整数」。网上常见序列 `[1,6,15,37...]` 用的是 round，与本实现 `ceil(15×2.5)=38` 不同——**这是刻意的选择**，若你想对齐 Anki 的 round 需改 `submitReview/index.js` 的 `Math.ceil`。
- [ ] **四档→q 映射是实现约定 `[假设]`**：again=2/hard=3/good=4/easy=5（q≥3 算通过）。本实现是**可解释的 SM-2 子集**，非 Anki 精确行为（Anki 现默认 FSRS + fuzz 扰动）。上线前确认这个简化符合你的产品预期。
- [ ] 配置控制台「用量」页日常查看，用 `_meta.dbReadCalls` / `approxWriteCalls` 回填实现要点 §5 的估算。
