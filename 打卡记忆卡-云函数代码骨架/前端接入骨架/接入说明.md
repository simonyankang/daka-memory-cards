# 前端接入骨架说明

> 把 4 个云函数（getToday / checkin / submitReview / importAnkiCsv）串成一条可用链路的前端逻辑骨架。
> 定位：**逻辑层 + 视图层 + 可导入工程配置**。本目录已补齐 `app.js/app.json/app.wxss/project.config.json/sitemap.json` 与三页完整 `wxml/wxss/json`（含 `today.wxs`），可直接作为小程序项目根导入微信开发者工具；样式是可用基础版，视觉按团队规范再美化即可。
> **组装必读**：云函数需按《工程组装与联调说明.md》§3 拷进本目录下的 `cloudfunctions/`，否则 `callFunction` 失败；AppID 占位 `touristappid` 必须替换。静态自检 68 项全通过，真机联调步骤见该说明 §4/§7。
> 前置：`app.js` 里 `wx.cloud.init({ env: wx.cloud.DYNAMIC_CURRENT_ENV, traceUser: true })`；云函数已按《部署与调用说明》部署；集合权限设「仅管理端可读写」。

## 2. 一条完整的数据流

```
[今日 today]
  打开 → api.getToday() ── 先读 wx.setStorageSync 缓存秒开 → 后台调 getToday 云函数覆盖
       → 渲染 user(连续/累计) + plans(打卡项) + reviews(待复习数)
  勾选打卡项 → 点「打卡」→ api.checkin(date, planIds)
       → 云函数 _.inc 自增 + 断签判断 + 固定 _id 幂等流水 → 清今日缓存 → 刷新

[复习 review]
  点「开始复习」→ 用 getToday 的 reviews（带 card 正文）
       → 逐张翻卡 → 四档(again/hard/good/easy)评分攒内存
       → 翻完一次 api.submitReview(results) → 云函数按 SM-2 批量更新排程
       → 统计 _.inc → 清今日缓存

[导入 import]
  选 CSV / 粘贴 → api.readCsvFile 读成文本 → api.importAnkiCsv(csv)
       → 云函数解析+去重+分批 add → 展示 新增/去重/失败
       → 新卡初始化 reviews(SRS 第 0 状态) → 之后随复习养成
```

## 3. 三个页面怎么接

| 页面 | 调用 | 关键入参 | 依赖返回字段 |
|---|---|---|---|
| `today` | `getToday` / `checkin` | `date`、`planIds` | `user.streak/checkinDays`、`plans[]`、`reviews[]` |
| `review` | `getToday` → `submitReview` | `items:[{cardId,rating}]`、`date` | `reviews[].card`、`submitReview` 的 `updated/failed` |
| `import` | `importAnkiCsv`(+`readCsvFile`) | `csv` 文本 | `inserted/dupInFile/dupInDb/failed` |

路由：在 `app.json` 的 `pages` 注册三页，`today` 设为首页；跳转见各页 `onGoXxx`（`navigateTo` / `navigateBack`）。

## 4. 三个容易踩的接入点

1. **复习反馈要「攒批一次提交」，不要翻一张调一次。**
   `review.js` 把评分攒进 `results`，翻完统一 `submitReview`。这是省调用的核心——逐张提交 = 每张 1 次云函数调用，攒批 = 整批 1 次 + 每张 1 次库写。100 张差约 100 次调用。

2. **`submitReview` 的 rating 必须是这 4 个字符串**：`again` / `hard` / `good` / `easy`（大小写不敏感）。q 值映射在云函数侧，前端只传档位名。传错会整批 400。

3. **「部分成功」看数值不看 code。**
   - `submitReview` / `importAnkiCsv` 返回 `code:0` 时仍可能有 `failed>0`——要展示失败数，别只看 code 就报全成功。
   - `checkin` 同日重复返回 `code:0, alreadyCheckedIn:true`，不是错误，UI 显示「今日已打卡」即可。

4. **缓存键带日期**：`cache:today:YYYY-MM-DD`，跨天自然失效，不会把昨天的待复习显示成今天。写操作（打卡/复习）后主动 `removeStorageSync` 当天键再刷新。

## 5. `getToday` 返回体（前端渲染的真实字段）

```js
{
  code: 0,
  date: '2026-11-12',
  user: { _id, _openid, streak, checkinDays, lastCheckin, totalReviews?, ... } | null,
  plans: [ { _id, title, enabled, sortOrder, ... } ],
  reviews: [ { _id, cardId, dueDate, interval, easeFactor, repetitions, lapses,
               card: { _id, front, back, tags, deckId, ankiGuid } | null } ],
  _meta: { dbReadCalls: number, dueCount: number, truncated: boolean }
}
```
- `reviews[].card` 可能为 `null`（卡片被删但排程还在）→ 前端 `review.js` 已 `.filter(r => r.card)` 跳过。
- `_meta.truncated=true` 表示单日待复习超云函数封顶（`MAX_DUE=500`）被截断 → 真用到几百张/天才需处理，通常不会出现。
- **`checkedToday` 当前骨架未由 `getToday` 直接返回**，`today.js` 用 `user.lastCheckin === date` 近似判断。若要精确，可在 `getToday` 里加一条「查当天 checkins 流水是否存在」并补字段（1 次读调用，按需）。

## 6. 首页 UI 态的两个近似（如实标注）

- **今日是否已打卡**：用 `user.lastCheckin === today` 近似。边界：若用户今天打了卡、但 `checkins` 流水被手动删，`lastCheckin` 仍在 → 显示已打卡（与 `checkin` 云函数的幂等判断一致，不算错）。
- **打卡项勾选态** `donePlanIds`：本次会话内存态，未持久化。要跨天保留「每天勾了哪些」，需读 `checkins.date=今天` 的 `planIds` 回填（可并入 `getToday`）。一期 100 人内自用，简化为当次勾选。

## 8. 自测清单（联调时逐项过）

- [ ] 首次进入：缓存为空 → 云端拉取 → 渲染 user/plans/reviews；再次进入秒开（缓存命中）。
- [ ] 打卡：连点两次 → Toast「今天已打卡」、`checkinDays` 只 +1、`checkins` 只 1 条流水。
- [ ] 断签：昨天没打卡今天再打 → `streak` 重置为 1、`checkinDays` 继续累加。
- [ ] 复习：翻 30 张全点「记住」→ 一次 `submitReview` → `updated=30`、排程 `dueDate` 按 SM-2 推后。
- [ ] 复习：点「忘了」→ 该卡 `repetitions=0`、`interval=1`、明天（次日）到期。
- [ ] 越权：改包伪造他人 `cardId` 提交 → `updated=0`、他人排程不变。
- [ ] 导入：带引号/逗号/换行的 CSV → 正确解析；同一份重导 → `inserted=0`（幂等）。
- [ ] 导入：超 2000 行 → 前端分批或收到 413；格式错 → 显示首条 `errors`。
