# CSV 导入格式规范（一期 · 纯文字）

> 配套 `importAnkiCsv` 云函数。一期只支持**纯文字 CSV**，不含图片/音频。
> 目标是让用户把 Anki 卡片（或手工整理的表格）导出成约定格式，粘贴/上传后批量入库。
> 标 `[假设]` 的为一期设计约定，非微信官方强制规则，可按实测调整。

---

## 1. 最小示例（照抄即可）

```csv
front,back,tags,guid,deckId
hello,"comma, inside",tag1 tag2,g1,deckA
"line1
line2","answer ""quoted""",tag3,g2,
飞,fly,动词,,
```

导入后：
- `hello` / `comma, inside` 成为一张卡，`tags=["tag1","tag2"]`，卡组 `deckA`；
- 第 2 行是**跨行字段**（引号内换行）与**双引号转义**（`""` → `"`）的示范；
- 第 3 行无 `guid`，系统按正文生成稳定哈希键去重。

---

## 2. 列定义

| 列名 | 必填 | 说明 |
|---|---|---|
| `front` | ✅ | 卡片正面（纯文字） |
| `back` | ✅ | 卡片背面（纯文字） |
| `tags` | 否 | 标签，多个用**空格**分隔，导入后转字符串数组 `[假设]` |
| `guid` | 否 | 稳定去重键。建议填 Anki 的 `guid` 列；留空则由 `front+back` 生成哈希 `[假设]` |
| `deckId` | 否 | 卡组标识，用于分组；留空则不分组 |

- 列名**忽略大小写与首尾空格**（`Front`/`FRONT`/` front ` 均可）。
- 表头必须包含 `front` 和 `back` 两列，缺任一列直接报错返回，不写库。
- 正负两列都为空的行自动跳过。

---

## 3. 转义规则（RFC 4180 子集，务必遵守）

一期解析器按以下规则处理 `[假设]`：

| 场景 | 写法 | 解析结果 |
|---|---|---|
| 字段含逗号 | `"comma, inside"` | `comma, inside` |
| 字段含换行 | 用双引号包裹，直接换行 | 保留 `\n` |
| 字段含双引号 | `"say ""hi"""` | `say "hi"` |
| 字段中间的**裸引号** | `quote "bare" mid` | `quote "bare" mid`（一期额外容错，原样保留） |
| 字段首尾空格 | 自动 `trim` | 去首尾空格 |
| BOM 头 | Excel「CSV UTF-8」导出的 `\uFEFF` | 自动剥离，不破坏表头 |

**分隔符固定为英文逗号 `,`**。Anki 或 WPS 若导出为分号 `;` / Tab 分隔，先在 Excel 里「另存为 CSV（逗号分隔）」或用文本编辑器替换分隔符后再导入。

---

## 4. 去重规则（决定重复导入会不会产生垃圾数据）

两层去重，**都命中则跳过、不覆盖已有卡与复习进度**：

1. **输入内去重**：同一份 CSV 中 `ankiGuid` 相同的行只留第一条 `[假设]`。
2. **查库去重**：按 `guid`（或哈希键）查询数据库，已存在则跳过。

`ankiGuid` 的来源优先级：
- 有 `guid` 列且非空 → 用该值（**推荐**，跨文件、跨导出都稳定）；
- 否则 → `h:` + 对 `front + 0x1F + back` 的 djb2 哈希 `[假设]`（同一正文必得同一键，跨导入可去重）。

> ⚠️ 若你修改了某卡正文且该行没有 `guid`，哈希键会变化，重导入会**新增**一张而非更新。需要"可更新"就给每行填稳定的 `guid`（用 Anki 自带的 guid 列最省事）。

去重带来一个好性质：**卡片正文（`cards`）与复习排程（`reviews`）分离**，重复导入不会产生新卡，更不会冲掉已有的 `interval/easeFactor/repetitions` 复习进度。

---

## 5. 限制与校验（防函数超时/内存爆）

| 限制 | 值 | 性质 |
|---|---|---|
| 单次导入行数 | ≤ 2000 行 | `[假设]` 云函数默认超时 15s，2000 是保守上限 |
| 单个字段长度 | ≤ 2000 字符 | `[假设]` 防单行撑爆返回体/内存 |
| 每批并发写 | 20 张 | `[假设]` 受控 `Promise.all`，兼顾吞吐与限流 |
| 输入方式 | `event.csv` 文本 | 一期纯文本；云存储文件走前端先读成文本 |

超限行为：返回明确错误码（`400` 格式/校验错、`413` 超行数），**不会**中途写了半截。

---

## 6. 从 Anki 导出 CSV 的建议路径（一期）

Anki 桌面端不直接产出本规范的 CSV，需过一道转换。可选：

- **路径 A（最省事）**：Anki → `File > Export` → 选 `Cards in Plain Text / CSV` 或装 `Anki Export` 插件导出含 `Front/Back/Tags/Guid` 的表 → 用 Excel 整理成上面 5 列 → 另存为「CSV UTF-8（逗号分隔）」。
- **路径 B（纯手工）**：卡片少时直接在 Excel/WPS 建 `front/back` 两列，逐行填，另存为 CSV。
- **路径 C（二期再做）**：直接给 `.apkg` 文件走云函数解 ZIP+SQLite（见实现要点 §4），一期不依赖它。

> 说明：Anki 各版本导出菜单与字段分隔符不尽相同，这里只给方向；具体以你本机 Anki 版本的导出界面为准，导出后统一整理成 §1 格式即可。

## 7. 前端调用片段（怎么把 CSV 传给云函数）

```js
// 选文件 → 读成文本 → 调云函数
wx.chooseMessageFile({
  count: 1,
  type: 'file',
  extension: ['csv', 'txt'],
  success(res) {
    const file = res.tempFiles[0]
    const fs = wx.getFileSystemManager()
    fs.readFile({
      filePath: file.path,
      encoding: 'utf8',
      success(r) {
        wx.cloud.callFunction({
          name: 'importAnkiCsv',
          data: { csv: r.data },
          success(out) {
            const d = out.result
            if (d.code === 0) {
              console.log(`导入 ${d.inserted} 张，输入内去重 ${d.dupInFile}，库中已存在跳过 ${d.dupInDb}，失败 ${d.failed}`)
            } else {
              console.error('导入失败', d.msg, d.errors)
            }
          },
        })
      },
    })
  },
})
```

> 粘贴场景（无文件）更简单：文本框 `textarea` 拿到字符串直接放 `data.csv`。

## 8. 格式自检清单（导入前对一遍）

- [ ] 首行是表头，含 `front` 和 `back`；
- [ ] 分隔符是英文逗号，不是中文逗号或分号；
- [ ] 含逗号/换行的字段已用双引号包裹，字段内引号已双写；
- [ ] 编码是 UTF-8（带不带 BOM 都行）；
- [ ] 行数 ≤ 2000，单字段 ≤ 2000 字符；
- [ ] 想让重导入可更新 → 每行填了稳定 `guid`。

---

## 9. 一期边界（明确支持 / 不支持，避免误解）

### 9.1 支持与不支持清单

| 能力 | 一期 | 说明 |
|---|---|---|
| 纯文字 `front`/`back` | ✅ | 唯一核心场景 |
| `tags`（空格分隔）/ `deckId` / `guid` 可选列 | ✅ | 见 §2 |
| RFC4180 引号/逗号/换行转义 + BOM | ✅ | 含字段中间裸引号容错，见 §3 |
| 输入内 + 查库两层去重 | ✅ | 重复导入不产垃圾、不冲掉复习进度，见 §4 |
| 从 Anki 导出后整理成 CSV 再导入 | ✅ | 见 §6 |
| **直接读 `.apkg`** | ❌ | ZIP+SQLite，需三方库 + Zstd 解压，二期 |
| **图片 / 音频媒体** | ❌ | 一期纯文字，不含 `media` 映射 |
| **Cloze 挖空 / 卡片正面含 HTML/LaTeX** | ❌ | 当纯文本存入，不解析模板 |
| **反向卡 / 多字段映射**（>2 列正文） | ❌ | 只取 `front`/`back` 两列，其余忽略 |
| **分号 / Tab 分隔** | ❌ | 需先转成逗号分隔，见 §3 |
| **导入即覆盖/更新已有卡** | ❌ | 命中去重键即跳过；要更新换稳定 `guid` 且先手动删旧卡 |
| **导入时保留 Anki 复习进度** | ❌ | 一期新卡统一初始化 SRS（interval=0/EF=2.5）；`.apkg` 的 ivl/factor 迁移在二期 |

> 一句话边界：**一期 = 「把纯文字卡片批量搬进来」**，不是「完整迁移 Anki 卡组与进度」。复习排程从导入当天的第 0 状态开始，由 `submitReview` 按 SM-2 逐步养成。

### 9.2 错误码语义（前端据此分支处理）

| code | 含义 | 是否写入了数据 | 前端建议 |
|---|---|---|---|
| `0` | 成功（含部分失败，看 `failed`/`failedSamples`） | 是（成功部分） | 展示 `inserted`，若有 `failed>0` 提示「部分失败，请重试或检查」 |
| `400` | CSV 格式错/缺列/空数据/字段超长 | **否**（整批拒绝） | 展示 `errors[0]`，引导按 §8 自查 |
| `401` | 无 OPENID（非小程序客户端调用） | 否 | 检查是否从 `wx.cloud.callFunction` 发起 |
| `413` | 超 `MAX_ROWS=2000` 行 | 否 | 提示分批导入（每次 ≤2000 行） |
| `500` | 云函数内部异常 | **可能部分写入**（见下） | 让用户稍后重导入——去重键保证已写入部分不会重复 |

### 9.3 幂等与部分失败（务必理解，否则会困惑）

- **幂等**：靠 `ankiGuid` 去重键。同一份 CSV 重导入，`inserted=0`、`dupInFile` 或 `dupInDb` 增加，**不会产生重复卡、不会重置复习进度**。可放心重试。
- **部分失败**：`batchInsert` 对每条 `add` 单独 `try/catch`，某条失败（如临时网络/限流）只计 `failed`，不中断整批。返回 `failed` 与最多 10 条 `failedSamples`。用户把失败行挑出来重导入即可（幂等保证已成功的不重复）。
- **「部分成功」的 code 仍是 0**，不是错误码。**成功条数看 `inserted`，失败看 `failed`**，不要只看 `code`。
- **写入非原子**：一批 20 条里可能成功 18 失败 2，没有事务回滚。这是刻意取舍——文档型数据库多文档事务有额外成本，且幂等重试已能兜住，100 人内纯文字场景足够。
- **无 `guid` 行的隐患**（重申 §4）：正文一改哈希键就变，重导入会新增而非更新。要稳定更新就填 `guid` 并先删旧卡。

### 9.4 建议的导入交互（前端）

1. 导入前先展示 §8 自检清单 + 本页 §9.1 不支持项；
2. 单次文件 >2000 行时前端按行切成多个 ≤2000 的批次，逐批调用（避免 413）；
3. 展示「新增 X / 文件内去重 Y / 库内已存在 Z / 失败 W」，失败时给 `failedSamples`；
4. 强调「重复导入安全」降低用户心理负担。
