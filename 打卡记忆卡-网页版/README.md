# 打卡 · 记忆卡（纯网页离线版）

一个手机浏览器就能打开的打卡 + 间隔重复记忆卡工具，支持从 Anki 导入 CSV 或 `.apkg`。没有后端、不联网上传、不上传任何数据。装到主屏后是 PWA，**断网也能用**。

这是同一个需求的第三次落地。最早按微信小程序云开发做了一整套（4 个云函数 + 完整工程 + 上线指南，在隔壁 `打卡记忆卡-云函数代码骨架/` 目录，保留未动），后来放弃小程序路线，改成现在这个纯网页版。核心的 SM-2 排程、CSV 解析、去重逻辑是从那套已通过 97 项自检的云函数逐行搬过来的，算法口径没变。二期新增的 `.apkg` 解析复用同一套入库逻辑（`core.js` 的 `importRows`），没有另起炉灶。

## 怎么开始用

**手机上用（推荐）**：把本目录发布成一个在线链接（WorkBuddy「发布为应用」，或 GitHub Pages / Vercel / Netlify / 腾讯云静态网站托管，把整个文件夹传上去即可），手机浏览器打开链接：

- **Android / Chrome**：页面顶部会出现「装到主屏幕」提示条，点「安装」即可；或浏览器菜单里选「添加到主屏幕 / 安装应用」。
- **iPhone / iPad**：必须用 **Safari** 打开 → 底部「分享」→「添加到主屏幕」。在「我的」页也放了同样的图文引导。微信里打开的，先点右上角「···」→「在 Safari 中打开」。

装好后从桌面图标打开是全屏的，和 App 一样，且已缓存程序文件，断网可用。

> **⚠️ 分享给别人时，千万别直接转发这条链接（重要）**：链接末尾的 `?sharecode=XXXXXXXXXX` 是发布平台的访问凭证，**微信转发或「复制链接」会自动洗掉 `?` 后面的参数**，对方打开就会看到一张标题为「链接不完整」的 403 页（不是 yours 程序坏了，也不是 Safari 的问题）。实测参数少一个字符、多一个、留空，全部 403。
>
> 三种可靠分享方式，按省事程度排：
> 1. **发二维码**（最稳）：把 `打卡记忆卡-扫码分享卡.png` 发给对方，让对方**先把图存到相册、退出微信，再用 iPhone 自带「相机」扫相册里的码**（扫开直接是 Safari）。**千万别用微信「扫一扫」或「长按识别图中二维码」**——那两种是微信自己的浏览器打开，实测会像转发一样洗掉 `?sharecode=` 参数，照样撞「链接不完整」403。扫码本身是把完整 URL 当纯文本直开、不经过转发清洗，前提是**用系统相机、走 Safari**。扫开后 →「分享 → 添加到主屏幕」。二维码是纯黑白高对比、57×57、H 级纠错，图片即使被微信压一遍也仍能扫出完整链接。
> 2. **发纯文本、手动粘贴**：把完整链接文本（含 `?sharecode=...`）发给对方，让对方**在 Safari 地址栏手动粘贴完整一整串**打开，不要在微信里点开再转。
> 3. **换无分享码的托管**：如 GitHub Pages / Vercel / 腾讯云 COS，链接是干净的 `https://xxx/`，微信怎么转发都不丢参数——代价是要另注册发布、国内访问速度另评估。
>
> 自己在自己手机上：只要第一次是用**完整链接**（或扫码）打开并「添加到主屏幕」，之后从桌面图标进就是带完整参数的，日常使用完全不受影响。

**电脑上稳妥用**：别双击 `index.html`（`file://`），改用本地静态服务器。装了 Python 的话，在本目录执行：

```
python3 -m http.server 8000
```

然后访问 `http://localhost:8000`。

> **为什么不能用 `file://` 双击**：MDN 明确写了 `file:` 地址下 localStorage 的行为是未定义的，各浏览器实现不一致，可能直接抛 `SecurityError` 存不住；而且当前浏览器倾向给每个 `file:` 路径配独立存储，换个文件夹打开就像数据"丢了"。更关键的是，二期的 `sql.js(wasm)` 和 Service Worker 都要求 `http(s)` 环境，`file://` 下 `.apkg` 解析和 PWA 缓存都无法工作。程序对 `file://` 有醒目提示，CSV 导入仍可用，但**不要拿 `file://` 存正式数据**。

## 数据存在哪，会丢吗

这是纯本地方案唯一要认下的事，说在前面：

- 全部数据存在**浏览器 localStorage** 里，就一个键 `daka-memocard-v1`，一个 JSON 对象。不上传、不联网、没有账号。
- Service Worker 只缓存**程序文件**（HTML/JS/wasm/图标），**不碰你的数据**。清缓存/站点数据会同时清掉数据和离线缓存，等于回到"时需联网打开"。
- 只要不主动清，数据一直在。**但下面几种情况会全丢**：清浏览器缓存/站点数据、换手机或换浏览器、用无痕/隐私模式（关掉最后一个隐私标签就会清）、卸载浏览器、部分手机管家清理。localStorage 按 origin（协议 + 域名 + 端口）隔离，http 和 https 下还是两份，跟着「设备 + 浏览器 + 站点」走，不是云同步的。
- 所以：**定期用「我的 → 导出备份」把 JSON 存到网盘或发给自己**。换设备时用「从备份恢复」导回来。这是纯本地工具唯一的保险，没有第二条。
- 如果你需要多设备自动同步或多人共用，那就得有后端，纯网页 localStorage 做不到——那条路是之前的云开发版，或者接一个云后端。

## 功能怎么用

四个页签，底部切换：

**今日**：顶部三个数（连续天数 / 累计打卡 / 待复习）。「今日打卡」里勾掉完成的事；点「添加」新建打卡项，可以填一个「关联卡组」名，填了之后这一项会显示该卡组今天还剩几张要复习。勾选和取消是手动的，程序不会替你判定。

**复习**：进入时按 SM-2 取出今天到期的卡（新导入的卡当天就到期）。先看正面，点「显示答案」看背面，再按想起来的程度点四档：忘了 / 吃力 / 想起了 / 很轻松，每个按钮会显示**按当前排程点下去后的下次复习时间**（用真实 SM-2 算，不是写死的）。评完即时存本地。

**卡片**：手工加卡、编辑、删除、按正面/背面/标签/卡组搜索。下面是 Anki 导入区。

**我的**：数据概况、导出/导入备份、清空（要手打「清空」二字确认）、调每日上限、装到主屏引导（iOS）。

### 从 Anki 导入

两条路，都进同一套去重与排程：

**A. CSV / 文本（一期，最稳）**：Anki 里把牌组导出为 CSV / 文本，逗号分隔，选文件或直接粘贴。表头认 `front`（必填）、`back`（必填）、`tags`、`guid`、`deckId`（后三个可选，忽略大小写与首尾空格）。字段含逗号/换行/引号时用双引号包裹，字段内引号写成两个。带 BOM 没问题。最小模板：

```
front,back,tags,guid
中国的首都是哪座城市？,北京,地理,g1
1 + 1 = ?,2,数学,g2
```

**B. `.apkg` 整包（二期，纯文字）**：直接选 Anki 导出的 `.apkg`，程序解包并读数据库，自动取文字，不需要你先转 CSV。行为：

- 读 `collection.anki2` / `collection.anki21` 里的 `notes.flds`，按 `0x1F`（单元分隔符）拆字段，**首字段为正面、其余合并为背面**；HTML 标签清洗成纯文字，`<img>` / `[sound:]` 媒体引用**剥离并计数**，不搬媒体本体。
- **Cloze 填空卡**（`{{c1::...}}`）跳过并计数——纯文字渲染不了填空。
- **正反面都为空**的跳过；**只有背面**的做防御性兜底（把背面当正面，避免丢卡）。按 Anki 官方规则本不会生成正面为空的卡，这只针对异常/手工改过的包。
- 有 `guid` 用 `guid` 去重（`a:` 前缀），没有就用正文稳定哈希（`h:` 前缀）。
- 首次解析要加载约 700 KB 的本地组件（`JSZip` + `sql.js` 的 wasm），稍等片刻；**组件进 SW 缓存后，离线也能解析**。
- 导入前同样有「预览解析结果」：告诉你会读多少 notes、剥离多少媒体/跳过多少 Cloze、文件内重复多少、将新增多少，确认无误再导入。

**两条路共同的规则**：单次最多 2000 行，超了提示拆分；重复导入不会产生新卡、也不会覆盖已有卡的复习进度，可放心重导。

#### `.apkg` 的兼容边界（实测，别踩坑）

| 情况 | 支持 | 说明 |
|---|---|---|
| 老版 `collection.anki2` | ✅ | 实测可读 |
| 新版命名 `collection.anki21`（未压缩 SQLite） | ✅ | 实测可读，字段一致 |
| `.colpkg` 整库包 | ✅ | 内部数据库条目同名，用同构样本实测可读（12 行）；导出的是"整个收藏"，导入时只会取其中的卡片文字，不会覆盖你现有数据 |
| 新版 `collection.anki21b`（**Zstd 压缩**） | ❌ | **读不了**，会明确提示。纯前端不引 Zstd 解压库，请在 Anki 导出时选「旧版/兼容格式」，或改用 CSV |
| 加密 / 损坏 / 非 Anki 的 ZIP | ❌ | 给出清晰错误，不会崩 |
| 图片 / 音频本体 | ❌ | 纯文字版不搬，引用会剥离 |
| Anki 的复习进度（ivl/factor） | ❌ | 导入的卡统一从零开始排程，不迁移 Anki 进度 |

这些是**实测结论**（见「自检与依据」），不是猜测。手上 `.apkg` 读不了时，最省事的兜底永远是先从 Anki 导出 CSV。

## 排程用的什么算法

SuperMemo 官方 SM-2，逐条对着原始公式实现的：

- 初始简易度 EF = 2.5，前两次间隔 1 天、6 天，之后 `间隔 = 上次间隔 × EF`，**小数向上取整**（官方 ceil 口径，不是四舍五入）。所以一直 Good 的序列是 `[1, 6, 15, 38, 95, …]`。
- `EF' = EF + (0.1 − (5−q)(0.08 + (5−q)×0.02))`，EF 低于 1.3 按 1.3 算。q=4 时 EF 不变。
- 四档映射到 q 值（**这是实现约定，不是 Anki 官方行为**）：忘了=2、吃力=3、想起了=4、很轻松=5；q≥3 算答对，答错则次数归零、间隔重置为 1 天、遗忘次数 +1。
- **Anki 现在默认用 FSRS 和自己的算法，还会加随机扰动，不是纯 SM-2。** 所以本工具是可解释的 SM-2 子集，复习日期会和 Anki 不完全一样。

## 发布平台的一个坑：manifest 为什么是内联的

WorkBuddy「发布为应用」给的分享链接形如 `https://xxx.app.workbuddy.host/?sharecode=XXXX`。平台的访问校验是：访问带头像码的首页时，用 `Set-Cookie: __wb_rsc`（30 天）下发凭证，**之后所有子资源请求都必须带这颗 cookie 才放行**，裸请求一律 403。

由此产生一个竞态：浏览器解析 HTML 时会自动 fetch `<link rel="manifest">`，这个请求可能**早于 cookie 落盘**而拿到 403，导致 PWA 装不上（403 是偶发的，取决于时序）。而 `<script>`、`fetch`、SW 注册都发生在页面 load 之后，cookie 已就位，不受影响。

解决方式：**不把 manifest 当静态文件 fetch，而是用 JS 在 load 后生成一个 `data:application/manifest+json;base64,...` 的 `<link>`**——零 HTTP 请求，彻底不依赖 cookie。清单里的图标 URL 用 `location.href` 拼成绝对 `https` 地址（用户点「添加到主屏幕」时 cookie 早已存在，图标可正常取）。`manifest.webmanifest` 文件仍保留在目录里，作为可读的清单副本；本地用 `python3 -m http.server` 打开时也能直接访问它。

换其他托管平台（GitHub Pages / Vercel / 腾讯云 COS 等）没有这颗 cookie 机制，静态 `<link rel="manifest">` 也能正常工作；内联写法在这些平台上同样有效，不会有害。
